# 产品契约与验收

## 一句话

满分选品工作台让任何已登录成员发起有证据门禁的选品任务，并把任务安全地分派给具备能力和容量的维护人员，直到形成可回溯的报告、资料包和结果回执。

## 固定用户流

```text
登录 → 发起选品 → queued → 自动分派或可认领
→ claimed → processing → review
→ completed / blocked / cancelled
→ 报告、候选、资料包、Feishu 回执、结果回流
```

## 完成定义

任务只有同时满足以下条件才可以 `completed`：

1. 研究适配器返回成功业务回执，包含 run id、执行器、开始与结束时间。
2. 报告或明确的 `insufficient_data` 产物通过 Schema 与来源检查。
3. 网站/数据库写入成功并读回对象版本。
4. 若启用 Feishu，卡片已校验并保存唯一发送回执；未启用则明确记录 `disabled`。
5. 任务负责人、实际执行人、状态变化和下一步都写入审计日志。

## YouTube 关联视频门禁

选品研究完成前，每个候选都必须完成一次 YouTube 检索。检索对象包括候选名称、中文名称、唯一主竞品、参考对象和玩法关键词；游戏候选还必须加入玩法、实机、演示、评测等关键词。

检索结果分为两种：

- `found`：找到至少一个可打开、与候选或主竞品明确相关的视频，保存 URL、标题、频道、发布时间、视频类型、关联对象、检索时间和来源说明。
- `insufficient_data`：在记录的关键词、时间范围和可访问范围内没有找到可确认视频，保存检索记录、失败原因和下一步补证动作。

候选详情、报告详情和制作档案都要显示视频入口。视频链接只能来自已记录的检索证据，不能由模型凭记忆拼接或把搜索页当成视频证据。

开工提示词必须包含“先搜索 YouTube 关联视频”的明确步骤，并把已找到的视频链接和未找到视频的限制带入后续研究。缺少 YouTube 检索回执时，候选最多停留在 `review` 或 `partial`，不能进入 `completed`、`READY_FOR_BENCH` 或正式开工。

## 权限

| 能力 | 普通成员 | 维护人员 | 管理员 |
| --- | ---: | ---: | ---: |
| 发起选品 | ✓ | ✓ | ✓ |
| 查看本人任务 | ✓ | ✓ | ✓ |
| 认领开放任务 | - | ✓ | ✓ |
| 更新本人任务 | - | ✓ | ✓ |
| 维护人员配置 | - | - | ✓ |
| 回收/重派任务 | - | - | ✓ |
| 修改全局容量 | - | - | ✓ |
| 查看全量审计 | - | - | ✓ |

## 核心指标

- `dispatch_latency_p95`：从入队到分派的 P95。
- `active_capacity_utilization`：当前进行中 / 全局上限。
- `claim_success_rate`：认领成功率与失败原因。
- `completed_with_evidence_rate`：有完整业务回执的完成比例。
- `stale_lease_recovery_time`：失联任务被回收的平均时间。
