# 参考标的分析：从“漂亮页面”转向“有时代感的工作台”

更新时间：2026-11-25（Asia/Singapore）

## 先否定上一版

上一版 A/B/C 原型暂不进入生产。问题不是颜色选得不够高级，而是：

- 仍然是通用 Dashboard 结构，左栏 + 卡片 + 指标块，没有独特的工作台对象。
- 圆角、渐变、环形进度和状态胶囊过多，像设计练习，不像真实的高频生产工具。
- “容量”“研究”“证据”“认领”没有形成有内在关系的视觉语法。
- 字体、材质、动效都没有建立品牌级规则，质感只能靠装饰补偿。
- 时代感不是霓虹色；时代感来自更少的噪音、更强的上下文、更快的操作和更精确的反馈。

## 参考标的

### 1. Linear：克制、密度、系统化

参考：[Linear 的 2026 UI refresh](https://linear.app/now/behind-the-latest-design-refresh)、[Linear brand](https://linear.app/brand)。

可借鉴：

- 导航主动退后，让当前工作区域获得视觉优先级。
- 通过统一的 header、view bar、间距和 token 系统处理复杂产品，而不是每页重新设计。
- 深色不是纯黑，而是带有层次的中性深色；强调色只用于真正需要决策的地方。
- 视觉精度来自细小的边界、字重、行高、图标和状态的一致性。

不能照搬：Linear 的核心对象是 issue/project；满分选品的核心对象是“机会 + 证据 + 负责人 + 进展”，必须做自己的对象层级。

### 2. Vercel Dashboard：导航重构与环境感

参考：[Vercel dashboard navigation](https://vercel.com/changelog/new-dashboard-navigation-available)。

可借鉴：

- 可收缩侧栏、统一 tabs 和项目/团队过滤器，让同一个页面承载不同工作范围。
- 桌面和移动端不是缩小版，而是分别设计最常用的入口。
- 环境、项目、部署、日志之间有清晰的上下文切换。

不能照搬：Vercel 的黑白极简容易让选品系统失去证据温度；我们需要保留少量“研究材料”的视觉线索。

### 3. Raycast：命令入口与个人工作流

参考：[Raycast](https://www.raycast.com/)、[Raycast press](https://www.raycast.com/press)。

可借鉴：

- 把“发起选品、认领任务、切换视图、查看回执”做成统一 command bar。
- 键盘优先，鼠标操作仍然完整；高频动作不应要求用户穿越多个页面。
- 搜索不是附加功能，而是产品的主入口和个人上下文切换器。

不能照搬：满分选品不能变成只有命令行的工具，证据链、容量和风险仍需被看见。

### 4. Warp：把执行过程变成可观察对象

参考：[Warp Terminal](https://www.warp.dev/terminal)、[Warp customization](https://docs.warp.dev/getting-started/quickstart/customizing-warp/)。

可借鉴：

- 每次执行都有可折叠、可检索、可回看的 block；任务不只是一个状态标签。
- agent、命令、工作区、分支和回执在同一界面里连续呈现。
- 主题、tab、权限和 secret redaction 都属于产品体验，而非后台设置。

不能照搬：我们不把研究任务做成终端模拟器；只借用“执行可观察”和“结果可追溯”的结构。

### 5. Granola / Craft：研究材料的空间感

参考：[Granola 101](https://docs.granola.ai/help-center/getting-started/granola-101)、[Craft](https://www.craft.do/about)。

可借鉴：

- Granola 把 upcoming、notes、spaces/folders、chat 放到同一上下文，适合借鉴“从输入到整理到追问”的连续感。
- Craft 的页面、卡片和文档结构适合借鉴证据阅读、长文本和结果归档的舒适度。
- 研究结果要像可继续工作的材料，而不是一排不可展开的 KPI 卡片。

不能照搬：温暖纸张风格不能覆盖队列、容量和异常状态；高频运营区仍需要清晰的系统反馈。

## 对满分选品的合成结论

我们要做的是 **“研究操作系统”**：

```text
Linear 的层级纪律
  + Vercel 的上下文导航
  + Raycast 的命令入口
  + Warp 的执行可观察性
  + Granola / Craft 的证据阅读空间
```

核心界面不再以“Dashboard 卡片”作为基本单位，而以三个对象组成：

1. **机会对象**：机会标题、产品形态、主对应竞品、证据完整度、下一步。
2. **执行对象**：负责人、容量、租约、阶段、执行器、最近心跳、阻塞原因。
3. **证据对象**：来源、时间、范围、摘录、冲突、可验证动作。

## 下一轮设计方向

### D · Obsidian Instrument / 黑曜仪表台

- 主材质：石墨、烟黑、低亮度边界；表面不做玻璃渐变。
- 交互骨架：左侧上下文栏 + 中央机会工作区 + 右侧执行轨；`⌘K` 打开命令层。
- 签名元素：每个任务都有一条“证据—执行—回执”连续轨迹，而不是单个进度环。
- 品牌色：冷银为基础，使用一种高饱和信号色区分“需要动作”的状态。
- 质感来源：字重、微边界、状态转场、短促回执，不靠装饰插画。

### E · Research Ledger / 研究账本

- 主材质：灰白、墨黑、纸张暖色只用于证据阅读层；运营层仍保持中性。
- 交互骨架：机会列表 → 证据抽屉 → 执行记录 → 版本时间线。
- 签名元素：每个候选有一条可展开的证据索引，点击来源直接落到对应摘录。
- 品牌色：单一深蓝或深绿作为动作色，红色只表示阻塞/风险。
- 质感来源：高质量排版、长文本呼吸、版本标记和可靠的展开/收起动效。

### F · Command Fabric / 命令织网

- 主材质：深色底、细网格、极少量电光色；任务像节点在工作流中流动。
- 交互骨架：全局命令栏 + 任务泳道 + 右侧实时执行日志。
- 签名元素：认领成功时任务从公共队列“接入”个人工作区，容量变化实时可读。
- 品牌色：按状态使用一组严格 token，禁止多色同时抢焦点。
- 质感来源：即时反馈、键盘快捷键、执行 block、可回放的状态变化。

## 评审标准

下一轮不再以“截图第一眼好不好看”评审，而以以下问题打分：

- 3 秒内能否知道现在最需要处理什么？
- 能否解释为什么任务分给某个人、为什么当前不能认领？
- 能否从候选结论回到具体证据，再回到执行回执？
- 高频操作是否有键盘入口和低摩擦反馈？
- 24 寸大屏、13 寸笔记本和移动端是否都保留上下文？
- 去掉所有装饰后，品牌是否仍然成立？
