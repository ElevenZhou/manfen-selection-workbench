# 任务队列工程质量复盘

## 本轮核查

- 并发领取使用“先选候选、再带 `status = queued` 条件更新”。同一任务并发领取时只有一个更新能产生变更，其他 worker 返回空任务，满足单任务单领取。
- 幂等键同时有预读和唯一索引。补充了唯一索引冲突后的回读，因此两个并发相同幂等键请求会复用先成功的任务，不把可恢复竞争返回成 500。
- 租约领取、心跳与回收使用相同的 `lease_id`。状态写回现在要求当前租约匹配，避免旧 worker 在任务被回收后覆盖新 worker 的结果。
- 增加显式状态转换表。终态不可回退，非法跨状态写回返回 409，完成态仍要求报告回执。
- 动态 schema bootstrap 对旧版 `selection_requests` 表采用逐列补齐，`updated_at` 使用无默认值的兼容迁移，避免 SQLite/D1 的非常量默认值错误。

## 仍需在部署前处理

- 事件写入与状态更新目前是连续调用，D1 单请求内没有统一事务封装。若状态更新成功后事件写入失败，审计会出现缺口。部署前应改为 D1 `batch()` 原子提交，或增加审计补偿任务。
- 队列表和事件表主要依靠运行时 bootstrap，尚未纳入完整 Drizzle migration journal。正式部署前要生成并在 staging 执行一次可回放迁移，确认旧表、索引和回滚策略。
- API 仍依赖现有应用认证边界，本轮没有新增 OIDC/角色中间件。生产环境需要把创建、领取、更新和管理员回收权限接入统一身份校验。
- `GET` 任务列表会触发租约回收，正式环境可增加独立 reaper 以避免只在有读取请求时回收。
