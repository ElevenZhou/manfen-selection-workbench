# 满分选品 Dashboard 多 AI 设计提示词

你是一名资深产品设计师、信息架构师和视觉设计总监。请为“满分选品”设计一个真实可用的桌面端 Dashboard 页面，并输出一张高保真视觉设计稿。

## 产品背景

“满分选品”是一个面向产品、研究和运营团队的 App 机会研究工作台。团队每天需要查看选品机会、认领研究任务、跟踪执行进度、检查证据质量、了解团队容量，并继续推动下一步。

页面的核心任务是让用户在 3 秒内回答四个问题：

1. 现在最需要处理的事情是什么？
2. 哪些任务可以被我认领？
3. 为什么某项机会处于当前状态？
4. 下一步应该点击什么？

## 页面必须包含

- 顶部栏：产品名称、当前工作范围、日期或周期、通知、用户入口
- 左侧导航：总览、机会池、选品任务、证据中心、团队与容量、复盘归档
- 页面主标题：明确表达今天的工作重点，不要使用空泛的“欢迎回来”
- 关键行动：一个清晰的“发起选品”按钮，一个清晰的“认领任务”入口
- 今日重点机会：至少 3 个机会对象
- 每个机会必须显示：机会名称、目标市场、产品形态、当前负责人、当前阶段、证据质量、下一步动作
- 任务进度区：显示进行中、待认领、待复核的数量
- 团队容量区：显示总容量、已占用容量、可认领容量、人员分配
- 证据回执区：显示来源回写、证据完整度、风险或冲突
- 最近活动区：显示具体的人、动作、时间和结果
- 右下或主区域的明确行动区：让用户可以快速继续工作

## 页面结构要求

请把它设计成真正的 Dashboard，而不是宣传海报、登录页、概念插画或纯粹的游戏界面。

信息层级必须是：

1. 当前需要处理什么
2. 机会和任务的状态
3. 负责人、容量和证据
4. 进一步查看详情的入口

页面需要有足够的信息密度，但不要把所有内容做成卡片。卡片、表格、列表、进度条、标签和留白要有明确分工。

使用清晰的 12 列网格。页面要适合 1440×900 桌面屏幕，也要考虑 1280×800 笔记本屏幕。

## 视觉要求

- 默认使用明亮背景，不要使用黑色或深色 Dashboard
- 不要使用 Codex、终端、赛博朋克、开发者控制台、霓虹科技感
- 不要使用玻璃拟态、泛滥渐变、装饰性环形进度、无意义的大数字
- 不要让主题插画、角色或道具抢过任务信息
- 主题应该是视觉皮肤，信息架构必须仍然像一个专业工作工具
- 避免所有面板都使用相同圆角、相同阴影和相同卡片模板
- 字体需要有层级：产品标题、页面标题、数据、正文、辅助信息各自清晰
- 状态颜色必须有明确语义：可认领、进行中、待复核、已完成、风险
- 保持文字可读，中文不要变形，不要堆叠过多装饰字体
- 让页面有创意和质感，但不要靠装饰制造噪音

## 主题变量

请只替换下面的主题变量，保持同一套 Dashboard 结构和同一组数据，用于横向比较。

### 主题 A：二次元研究社

明亮的淡紫、天蓝、珊瑚粉和奶油白。可以使用轻量的角色头像、徽章、任务称号和小型任务奖励，但不要出现具体动漫 IP、夸张角色立绘或满屏游戏 HUD。整体感觉应该像一个成熟的二次元产品团队工作台。

### 主题 B：金融研究台

象牙白、浅灰、深海军蓝、绿色、琥珀色。可以使用市场脉冲、风险等级、机会配置、趋势线和容量分配。保持冷静、可靠、可审计。不要做成股票交易软件，也不要出现币价、K 线交易、金融品牌或黑底终端。

### 主题 C：休闲游戏厅

暖奶油色、湖蓝、橙红、黄、深棕。可以使用街机按钮、票券、积分、关卡和高分榜作为轻量反馈。任务信息必须仍然优先，不能做成儿童游戏首页，也不能让街机插画覆盖数据。

## 输出要求

请输出：

1. 一张完整的桌面端 Dashboard 高保真视觉稿
2. 页面必须展示完整状态，不要只画空状态或首屏 Hero
3. 必须能看出用户下一步要点击哪里
4. 必须能看出任务为什么处于当前状态
5. 必须保留任务、证据、负责人、容量之间的关系
6. 使用真实中文界面文字，不要用 Lorem ipsum
7. 不要放水印、设计软件界面、设备外框、浏览器窗口或多张拼贴图
8. 画面比例建议 16:10，适合 1440×900

## 设计评审标准

生成后请根据以下标准自检：

- 3 秒内能否找到最需要处理的任务
- 认领入口是否明显但不过度抢焦点
- 是否能快速区分待认领、进行中、待复核和风险
- 是否能同时看到机会、负责人、容量和证据质量
- 主题是否增加了识别度，同时没有破坏工作效率
- 页面是否像一个每天会使用的产品，而不是一次性宣传图
- 去掉主题装饰后，信息结构是否仍然成立

请优先保证信息层级、真实工作感和长期使用舒适度，再处理主题装饰。
