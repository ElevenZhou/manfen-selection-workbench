# 飞书选品报告发布规范

> 版本：v1.1  
> 目标：让每次选品结束后的经营结论自动到达飞书，同时确保内容完整、链接可用、视觉清楚且不会重复发送。

## 1. 发布边界

飞书发布发生在统一网站完成报告入库之后。网站入库失败时，不得发送一个没有正式报告地址的“成功通知”。

一张卡片只对应一份报告。三条路线可以同时出现在卡片中，但必须分段展示，不混合评分和排名。

完整报告链接统一使用公开地址 `https://select.1add2.com` 下的报告详情页，收件人无需登录 ChatGPT 即可阅读；不得把本地地址、预览地址或带临时凭证的链接写入卡片。

## 2. 必须包含的内容

- 报告名称、报告期和简短概述；
- 最终入选数量与生产资料包数量；
- 每个最终入选项目的名称；
- 每个入选项目的产品形态标签；
- 每个项目的参考品、竞品或替代方案名称及实际对象类型；
- 参考品为真实 App 时链接官方 Apple App Store / Google Play，并显示商店类型；非 App 研究对象链接“证据来源”；
- 每个 `READY_FOR_BENCH` 项目的生产资料包下载地址；
- 每个正式入选项目的制作档案链接；
- 每个正式入选项目的默认开工提示词预览；完整提示词以制作档案页为唯一可复制来源；
- 统一网站中的完整报告地址。

所有英文产品名和参考品名必须显示为 `English（中文）`。保留英文官方名与链接，不用中文翻译替换品牌身份。

产品形态、参考对象类型和链接语义统一遵循 `docs/14-产品形态与参考对象分类规范.md`。

## 3. 卡片视觉

使用飞书原生互动卡片：

- 蓝色标题栏与 `📊` 报告图标；
- `🔵 A`、`🟠 B`、`🟢 C` 作为路线视觉标识；
- 粗体产品名、紧凑指标、分隔线；
- 参考品使用名称链接，不展示裸 URL；真实 App 的目标地址仍优先进入官方商店；
- 参考对象名称后显示其实际类型，例如 `移动 App`、`手机游戏`、`Web 产品`、`开源项目` 或 `研究报告`；
- 资料包使用 `📦 生产资料包` 链接；
- 底部使用主按钮“查看完整选品报告”。

飞书卡片不支持任意字号 CSS。字号层级由原生标题、正文、备注、粗体和按钮形成。

## 4. 两种调用

### 总控自动调用

`app-selection-loop` 在完成网站入库后调用 `app-selection-feishu-publisher`：

```text
notify_feishu: true
idempotency_key: {run_id}:feishu-summary:v1
```

### 网站人工调用

“选品报告”列表和报告详情页提供“推送飞书”按钮。一次点击生成一个 UUID；同一个请求被浏览器或网络回放时仍只发送一次。

## 5. 安全、校验和回执

- Webhook 只来自服务端环境变量 `FEISHU_SELECTION_WEBHOOK_URL`；
- 前端代码、网站 JSON、卡片 JSON、日志、Git 和资料包中不得出现真实 Webhook；
- 外部引用只允许 `http://` 或 `https://`；
- 相对资料包地址必须使用线上网站域名转换为绝对地址；
- 发送前先生成并校验卡片 JSON；
- 只有 HTTP 200 且响应 `code=0` 或 `StatusCode=0` 才算送达；
- 每次发送在 D1 或本地回执中记录幂等键、报告 ID、状态、时间和供应商响应；
- 失败不自动重试，成功不为了确认而再次发送。

## 6. 运行产物

每个选品运行的发布目录增加：

```text
05-publish/
├── website-report.json
├── import-receipt.json
├── feishu-card.json
└── feishu-receipt.json
```

生成卡片但未被授权发送时，只保存 `feishu-card.json` 并标记 `generated`，不能标记 `delivered`。
