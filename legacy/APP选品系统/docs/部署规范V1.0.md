# APP 选品系统部署规范 V1.0

版本：V1.0  
日期：2026-11-11  
适用范围：内部最多约 10 人使用的 APP 选品驾驶舱及其后台任务链路

## 1. 结论

默认采用 Cloudflare / Sites 托管，不先购买独立 VPS。当前系统使用 Cloudflare Worker 运行 Web 与服务端 API，D1 保存结构化数据，后续使用 R2 保存资料包和附件，使用 Queues / Workflows 执行长任务。

10 人规模的主要风险不是页面并发，而是研究任务、模型调用、外部 API、文件生成和失败重试。长任务必须异步化，不能阻塞 Web 请求。

## 2. 能力边界

### 2.1 Cloudflare 可承载

- Next/Vinext 页面和 Worker 请求处理；
- Route Handler 后端 API；
- D1 数据库读写；
- R2 文件和资料包存储；
- 服务端 Secrets、身份校验和 Webhook；
- Cron 定时触发；
- Queues / Workflows 异步任务、重试和状态推进。

### 2.2 不直接承载

- 常驻 Node 进程；
- 本地模型或 Docker 服务；
- 长时间 Playwright 浏览器任务；
- 需要完整 Linux 文件系统的脚本；
- 在单次 HTTP 请求中持续运行的研究任务。

上述能力需要单独的后台执行器。执行器可以使用 VPS 或其他受控运行环境，Web、D1 和公开入口不必迁移。

## 3. 当前代码状态

当前已具备：

- Worker 入口和 D1 `DB` binding；
- `GET/POST /api/reports`；
- `POST /api/selection-requests`；
- `POST /api/reports/:id/feishu`；
- 服务端 ChatGPT 身份校验；
- 服务端飞书推送。

当前尚需补齐：

- Queue/Workflow consumer；
- 任务状态查询、事件记录和失败重试；
- 任务取消和超时；
- R2 附件存储；
- staging / production 分离；
- `/api/health` 与部署记录；
- 内部访问控制和角色权限。

`queued` 只代表任务已经写入 D1，不代表任务已经执行、报告已经生成或飞书已经发送。没有执行回执时必须保持 `PENDING` 或 `UNKNOWN`。

## 4. 环境划分

至少建立两个环境：

- `staging`：测试迁移、Queue、外部 API、权限和回滚；
- `production`：内部正式使用，禁止直接使用开发密钥。

每个环境独立配置 D1、R2、Queue、Secrets 和域名。生产密钥只通过 Cloudflare Secret 注入，不写入 Git、报告、资料包、前端响应或日志。

## 5. 内部访问与安全

当前公开网站适合报告阅读；内部操作台必须增加身份验证。推荐使用 Cloudflare Access 或 OIDC，并按角色限制报告入库、飞书推送、任务创建和配置修改。

必须启用：

- HTTPS、HSTS 和安全响应头；
- 管理接口身份校验；
- Webhook 签名、幂等键和重试上限；
- API 速率限制；
- 敏感字段脱敏；
- 操作审计日志；
- D1 迁移和 R2 文件备份策略。

## 6. 任务运行规范

任务流程统一为：

```text
创建任务 → D1 写入 → Queue/Workflow 执行 → 事件回写
→ 产物校验 → 报告入库 → 可选飞书推送 → 保存回执
```

每个任务必须保存：任务 ID、幂等键、请求人、执行器、开始和结束时间、状态、产物、错误、重试次数及回执。

外部连接器遵循超时、单次重试、退避和 `insufficient_data` 规则。支付、账号权限、域名 DNS 或凭证失败时硬停，不自动换凭证或无限重试。

## 7. 发布验收

发布前必须完成：

1. `npm ci`；
2. `npm run lint`；
3. `npm test`；
4. `npm run build`；
5. D1 migration 在 staging 成功；
6. 报告读取、报告入库幂等和权限接口 smoke test；
7. Queue 成功、失败、重试和超时路径验证；
8. 飞书推送读到 HTTP 状态、业务 code 和一次性回执；
9. 真实内部入口访问验证；
10. 记录版本、提交哈希、迁移编号、健康检查和回滚版本。

没有真实回执时，不得标记“已部署”“已生效”“已推送”。

## 8. 扩容触发条件

10 人内部使用时，优先继续使用 Cloudflare。只有出现以下情况才增加独立后台服务器：

- 需要常驻 Agent 或 Docker；
- 同时运行多个浏览器自动化实例；
- 需要本地模型或长期进程；
- Queue 任务持续堆积并超过可接受时延；
- Worker 执行时间或运行时限制成为明确瓶颈。

后台服务器起步建议为 4 vCPU、8 GB RAM、80 GB SSD；Web 和 D1 仍保留在 Cloudflare，后台执行器通过受限 API 与其通信。

## 9. 回滚与状态纪律

每次生产发布遵循：盘点 → 备份 → staging → canary → 验证 → 放量 → 回写记录。验证失败立即回滚，不继续放量。

“已排队”“已生成草稿”“页面可打开”都不能替代真实执行、发布或业务回执。状态必须与可读证据一致。
