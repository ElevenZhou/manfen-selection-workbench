# 图文综合主题设计与设计稿交付规范

> 状态：生效。适用于把已确认的选品结果交给 Google AI Studio、独立开发台或其他产品制作工作台。
>
> 目的：避免只输出文字版“主题设计”就进入开发。操作员必须同时看到可比较的文字方案和真实视觉设计稿，再做选择。

## 1. 强制交付原则

主题设计不是纯文字环节。每套候选方案必须完成以下闭环：

1. 先基于研究证据提出 3 套差异明显的主题/品牌/视觉方案；
2. 为每套方案写清定位、世界观、故事起点、玩法表达、视觉系统、色彩、字体、材质、关键界面与风险；
3. 使用当前可用的最高质量图像生成能力，把每套方案做成可查看的设计稿。不得用“可以生成”“建议参考”或纯文字占位代替；
4. 设计稿至少包含：品牌/主视觉板、核心场景或玩法画面、关键页面（移动产品至少 3 张，游戏至少 3 个关键场景）；
5. 给每张图附上方案 ID、画面用途、生成提示词、生成模型/模式、生成时间和待验证项；
6. 以图文对照表交给操作员选择。操作员选择前，不得开始完整编码；
7. 选择结果、未选方案和设计稿全部留档，便于复盘和后续迭代。

## 2. 设计稿质量门槛

- 图像必须能表达层级、构图、色彩、材质、空间和交互状态；
- 关键文字、按钮和数值使用后期排版或明确标注，避免把生成图中的乱码当成最终 UI 文案；
- 方案之间要有真正的视觉差异，不得只换色或换标题；
- 设计稿是方向验证稿，不代表已获得第三方资产授权，也不替代最终 UI 资产生产；
- 若图像工具不可用，必须明确标记 `DESIGN_IMAGE_BLOCKED`，保存完整图像提示词和低保真线框，暂停“已完成设计”的表述。

## 3. 推荐留档结构

```text
artifacts/design-directions/<project-id>/
├── 00-index.md                 # 方案索引、选择状态、版本和回执
├── 01-direction-a/
│   ├── concept.md              # 文字设计说明
│   ├── image-prompts.md        # 每张图的完整提示词与参数
│   ├── hero-board.png          # 主视觉板
│   ├── key-screen-01.png       # 关键页面/场景
│   └── key-screen-02.png
├── 02-direction-b/...
├── 03-direction-c/...
└── operator-choice.md          # 操作员选择、理由、时间和后续动作
```

若工作台有自己的产物目录，保持同样的字段和文件命名，不得只在聊天记录中留存。

## 4. 操作员选择卡

每套方案必须按同一顺序呈现：

- 方案 ID / 名称
- 一句话定位
- 文字设计摘要
- 主视觉板
- 核心场景/关键页面图
- 视觉系统摘要（色彩、字体、材质、动效）
- 与参考产品的关系和原创边界
- 主要风险与待验证项
- 选择：`A` / `B` / `C` / `要求重做`

选择记录至少包含：`project_id`、`direction_id`、`operator`、`selected_at`、`reason`、`revision`。
