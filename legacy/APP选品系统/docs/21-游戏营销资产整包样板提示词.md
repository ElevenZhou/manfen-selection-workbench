# 游戏营销资产整包样板提示词

> 用途：扫描一个真实游戏项目，根据代码、配置、设定、美术、截图和音频，生成可提交 Git 的游戏官网、商店资料、自媒体素材和宣传视频方案。网页提示词库中的卡片只展示摘要，展开和复制使用下面这份完整模板。

```text
请扫描当前游戏项目目录（读取代码逻辑、美术资源、配置表、设定文档及现有截图），基于项目的真实内容与视觉资产，为我生成一套完整的游戏官网、App Store 上架资料、自媒体宣传图文及宣传视频生成方案。

本提示词必须完整执行。可以根据真实项目补充不足、优化表达和调整实现方式，但不要为了展示简洁而删减任务、目录、规格、交付物或验证要求。

所有生成的文件请统一输出到项目根目录下的 _marketing_assets/ 文件夹中，并按以下结构分类存放：

_marketing_assets/
├── copywriting/
│   ├── 01_main_descriptions.md
│   ├── 02_feature_highlights.md
│   └── 03_appstore_metadata.md
├── social_graphics/
│   ├── 20_posts_plan.md
│   ├── generate_graphics.py（或 Node.js Canvas/Sharp 脚本）
│   └── output/
├── website/
│   ├── index.html
│   ├── styles.css（或内嵌 TailwindCSS/CSS）
│   └── script.js
├── videos/
│   ├── video_scripts.md
│   ├── generate_videos.py
│   └── output/
└── raw_assets/

---

## 一、游戏文案与商店上架资料（输出至 _marketing_assets/copywriting/）

请仔细阅读项目中的设定、玩法机制和关卡/角色数据，输出以下 Markdown 文档：

### 1. 核心游戏介绍（3 个不同风格的完整版本）
保存为 01_main_descriptions.md。

- 版本 A（硬核/玩法向）：突出核心机制、操作手感与策略深度。
- 版本 B（世界观/沉浸向）：突出美术风格、剧情设定与氛围感。
- 版本 C（简洁/吸睛向）：适合 App Store 简介开头及自媒体快速种草，节奏明快、有记忆点。

### 2. 卖点与二级介绍（4 组）
保存为 02_feature_highlights.md。

提炼游戏的 4 个核心亮点，例如独特机制、美术表现、角色/养成系统、关卡设计等。每组必须包含：主标题（8 字以内）、副标题（15 字以内）、详细说明（50–100 字）。内容可以直接用于 App Store 宣传图配字及官网分屏介绍。

### 3. App Store 上架元数据清单
保存为 03_appstore_metadata.md。

必须包含：应用名称（主标题 + 副标题）、宣传文本（170 字符以内）、关键词（100 字符以内，逗号分隔）、版本更新日志模板、隐私政策与技术支持页文案框架。对项目中没有证据的信息标注待补，不得编造功能、角色、数值、平台或授权信息。

---

## 二、20 套自媒体与商店宣传图文方案（输出至 _marketing_assets/social_graphics/）

结合项目中现有的美术素材（角色立绘、UI 元素、场景图、现有截图等），规划 20 套图文素材，输出为 20_posts_plan.md，并编写自动化图片合成脚本（例如 Python Pillow 或 Node.js Canvas/Sharp），在 _marketing_assets/social_graphics/output/ 中直接批量生成基础版海报。

### 规格覆盖

兼顾 App Store 预览图比例，例如 1290×2796 或 2796×1296，以及自媒体比例 3:4、1:1。每套方案要明确目标平台、画布尺寸、使用的项目源素材相对路径、画面构图建议、图片上的主标题和副标题、发布时的正文配文、Hashtag、CTA 和素材状态。

### 内容分配（共 20 套）

- 第 1–5 套：App Store 核心商店展示图（主视觉 + 4 大核心卖点，带文案排版）。
- 第 6–10 套：世界观/角色/设定图鉴展示（调用项目中的角色与场景原画）。
- 第 11–15 套：核心玩法与机制拆解图（展示数值、连招、策略或关卡特色，只有项目存在对应内容时才能使用）。
- 第 16–20 套：自媒体互动、悬念、开发日志向图文（适合小红书、X/Twitter、抖音图文发布）。

每套不能只更换颜色或标题，必须从不同视角表达游戏玩法、目标用户或使用场景。合成脚本要读取真实素材，生成基础版输出并报告缺少的素材、字体或依赖。

## 三、游戏官方宣传网站（输出至 _marketing_assets/website/）

直接生成一个现代、高质感、响应式的单页游戏官网（HTML + TailwindCSS/CSS + JS），确保双击 index.html 即可本地预览，且可直接部署。

### 视觉规范

自动提取游戏主视觉色调与字体风格，直接引用项目目录中的真实游戏素材，包括 Logo、背景图、角色立绘和实机截图。优先将实际使用的素材复制一份到 _marketing_assets/raw_assets/，保持网页和素材包独立可移植。

### 页面模块

1. 首屏 Hero 区：游戏 Logo、Slogan、App Store 下载按钮占位、动态视觉背景。
2. 核心卖点展示区：融入前面生成的 4 组二级介绍与对应画面。
3. 角色/世界观图鉴轮播：交互式切换查看项目中的角色或关卡设定。
4. 媒体画廊（Gallery）：展示高清截图与宣传视频占位区。
5. 页脚（Footer）：社交媒体链接、隐私政策弹窗或页面、联系我们和技术支持入口，满足 App Store 审核对官网、技术支持与隐私链接的要求。

所有 HTML、CSS、JS 中引用的图片、字体和音频路径必须真实存在。没有真实素材时使用明确的待补状态和可替换路径，并在交付清单中列出，不得伪造素材。

---

## 四、4–6 套游戏玩法介绍视频方案及自动化合成（输出至 _marketing_assets/videos/）

无需运行游戏进行实时录屏。请直接利用项目现有的设定图、立绘、UI 素材、音效/BGM 以及目录中已有的静态截图，制作 4 到 6 套宣传视频方案，兼顾 App Store 预览视频 15–30 秒规格与自媒体短视频竖屏规格。

### 1. 分镜脚本与剪辑表
保存为 video_scripts.md。

涵盖 4–6 个不同主题，例如：

1. 概念宣传片 PV。
2. 核心玩法演示。
3. 角色/技能展示。
4. 关卡/Boss 挑战。
5. 爽点/高光集锦。
6. 发售倒计时/悬念预告。

详细列出每个镜头的时长、调用的项目素材路径、运镜方式（推拉、摇移、缩放、震动）、字幕文案及配乐/音效节点。每套写清视频比例、分辨率、帧率、总时长、前 2 秒钩子、结尾 CTA 和可以替换的素材。

### 2. 自动化视频合成脚本
保存为 generate_videos.py。

使用 moviepy 或 ffmpeg，编写可直接运行的脚本，将项目里的静态素材、截图、文字图层和音频自动合成为带转场与动态缩放（Ken Burns 效果）的 .mp4 成品视频，并输出到 _marketing_assets/videos/output/。脚本应支持 dry-run，在缺少素材、音频或依赖时给出清晰错误和待补清单，不伪造成品。

---

## 执行要求

1. 先扫描再动手：先列出你在项目目录中找到的关键美术资源、截图、音效、BGM、配置表、设定文档和代码入口，确认你已充分理解游戏内容。扫描清单要包含真实相对路径、文件类型、尺寸（适用时）、用途和授权状态。
2. 路径准确：所有脚本和网页引用的图片、音频、字体和视频路径必须真实存在于当前目录中。建议将用到的素材复制一份到 _marketing_assets/raw_assets/ 保持独立可移植性。
3. 分步交付：确认扫描结果后，按“文案 → 官网 → 20 套图文脚本与基础合成 → 视频脚本与合成脚本”的顺序逐步生成并验证代码可运行。
4. 代码与产物验证：检查 Markdown、HTML、CSS、JS、Python 语法，运行图片和视频脚本的 dry-run 或实际生成，核对输出文件、画布尺寸、引用路径和 Git 可提交性。
5. 证据与风险：对缺失素材、未知设定、字体/音乐/图片授权风险、无法实际生成的内容逐项列出，并给出下一步补齐项。不要把推测写成项目事实，不要擅自提交 App Store、开启广告或购买素材。
6. 最终交付：输出生成文件清单、关键运行命令、验证结果、缺失资产、授权风险和待操作员确认的事项。完成的图片、视频、文案和脚本都放在项目子文件夹中，并可以直接提交到 Git。
```
