# RebBull 案例复刻创新与正式 App 选品提示词

使用 `$app-opportunity-scout` 执行一次 `competitor-expand` 正式选品。

## 一、任务目标

以 `RebBull（rebull.cn）` 为案例锚点，研究“AI 股票分析 Agent”赛道，识别可以合法复刻、必须重构和不可复制的部分，并输出最多 `3+1+1`：

- 最多 3 个 `SELECTED` 正式主选；
- 最多 1 个 `BACKUP` 备选；
- 最多 1 个 `WATCH` 观察项。

数量是上限，不是配额。证据门槛未通过时必须少选，不能降级证据标准凑数。

## 二、私有体验与安全边界

- 登录地址、账号与密码只从 `/Users/xmm/projects/APP选品系统/有账号密码的案例.md` 读取；
- 仅用于本次已授权的只读产品体验；
- 不在报告、日志、网站数据、截图或代码中输出账号、密码、Cookie、Token；
- 不进行交易、下单、充值、续费、改密、授权券商或其他外部副作用；
- 若出现验证码、风控或访问限制，记录阻塞，不绕过。

## 三、必须回答的问题

### 1. RebBull 产品拆解

- 核心用户、核心任务、触发场景和付费理由；
- 核心功能、关键页面、输入、输出、数据新鲜度、引用方式和风险提示；
- 完成一次个股分析的完整流程与最小闭环；
- 哪些是通用机制、哪些需要重构、哪些属于品牌/内容/数据等不可复制资产；
- 只对实测内容标记 `observed`；无法访问或无法验证的部分标记 `unknown` 或 `hypothesis`。

### 2. 用途与价值

- 它是在做资料检索、选股、诊股、组合监控、风险解释、策略回测还是交易执行；
- 相比同花顺问财、东方财富妙想、TipRanks、Danelfin、Fiscal.ai/FinChat、Simply Wall St 等竞品，减少了哪些步骤；
- 用户为什么持续使用或付费，而不只是试用一次。

### 3. 技术架构

按层拆解并区分“可验证事实”和“推荐实现”：

- 数据源与授权；
- 实时/批量采集、清洗、实体与证券代码对齐；
- 时序数据库、文档库、向量索引、知识图谱与缓存；
- 财务指标、技术指标、事件与情绪计算工具；
- Agent 编排、工具调用、检索增强、引用、冲突检测和确定性计算；
- 模型路由、成本、延迟、评测、幻觉控制；
- Web/App 前端、鉴权、VIP 计费、用量限制；
- 审计日志、合规免责声明、敏感操作隔离。

### 4. 数据接口可行性

分别判断：

- RebBull 是否提供公开、授权、稳定的 API；
- VIP 网页内部请求是否只是私有接口；
- 即使能在浏览器网络面板看到 JSON，是否具有调用、保存、再分发和商业使用授权；
- 合法替代数据源：Tushare Pro、聚宽/JQData、交易所/公告、SEC EDGAR、Alpha Vantage、TipRanks API/MCP、Danelfin API、Fiscal.ai API 等；
- 输出结论必须使用：`可直接使用 / 需商务授权 / 仅限内部验证 / 不建议使用`。

不得把“技术上能请求”写成“法律与商业上可用”。

## 四、竞品与需求证据

- 每个 `SELECTED` 至少 3 个命名直接竞品及可访问官方产品页或官方商店页；
- 至少两类独立证据支持需求或使用；
- 所有数字记录市场、平台、周期、采集日期、来源 URL 和 `value_type`；
- 分析正向价值、重复痛点、功能请求、定价/付费墙、数据准确性、同步、隐私与合规；
- 市场估算不能写成官方事实；
- RebBull 是案例锚点，不自动等于需求已验证。

## 五、创新原则

每个候选只允许 1–3 个核心改变，并同时满足：

- 对应重复用户痛点或可测量流程问题；
- 改变准确性、时间、信任、成本或完成率；
- 1–3 周可验证最小闭环；
- 不是换品牌、换颜色或简单加聊天框；
- 不复制竞品品牌、文案、私有内容、模型输出、受限数据或未公开接口。

AI 只在减少步骤、提高准确性、完成个性化工作流或形成持续监控闭环时使用。

## 六、正式门禁

`SELECTED` 必须全部满足：

- 直接竞品数 ≥ 3；
- 数据完整度 ≥ 80%；
- 路线分 ≥ 75/100；
- 重复用户价值与重复用户痛点都有证据；
- 一个人群、一个核心任务、一个清晰差异；
- 有下一次验证、继续指标与停止条件；
- 金融数据授权、合规边界和“非投资建议”方案可行。

自动交易、代客决策、收益承诺、无来源预测或依赖私有接口的方案即使分数高，也必须降级为 `WATCH` 或 `REJECTED`。

- `run.json`
- `candidates.json`
- `candidates.csv`
- `evidence.json`
- `evidence.csv`
- `review-themes.csv`
- `signals.json`
- `website.json`

2. RebBull 案例结论；
3. 最多 3+1+1 决策表；
4. 正式主选深拆；
5. 竞品与用户价值/痛点；
6. 推荐技术架构；
7. 数据接口可行性与授权判断；
8. 备选、观察与否决原因；
9. 缺失证据、下一次验证和停止条件；
10. 直接来源列表。

不部署网站、不推送飞书，除非用户另行明确授权。
