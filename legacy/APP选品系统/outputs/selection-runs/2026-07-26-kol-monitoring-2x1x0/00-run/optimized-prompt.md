# KOL 监控、AI 分析与推送专项正式运行提示词

使用 `$app-selection-loop` 完成一次不可覆盖的正式专项选品。

## 运行合同

- `operation_mode`: `WEEKLY_SELECTION`
- `direction`: `KOL monitoring + AI analysis + evidence-backed push`
- `markets`: `Global / 中国出海团队`
- `product_forms`: `Web 优先；仅在核心任务必须移动端完成时使用移动 App`
- `data_cutoff`: `2026-07-26`
- `route_A_final`: `2`
- `route_B_final`: `1`
- `route_C_final`: `0`
- `notify_feishu`: `false`
- `website_publish`: `true`

## 研究问题

1. 哪些品牌、代理、投资、战略或研究团队正在持续跟踪 KOL、达人、专家和高影响账号？
2. 他们真正要完成的是发现达人、监控合作内容、识别品牌风险、追踪观点变化，还是把信息交付给团队？
3. 现有达人营销平台、社交情报平台、RSS/提醒工具和人工流程分别解决了什么，在哪一步产生噪声、遗漏、解释断层或协作成本？
4. AI 是否可以把原始内容转成带来源的变化、影响和动作，而不是生成无依据摘要？
5. 推送如何控制严重度、聚合、冷却、人工确认和撤回，避免把“更多通知”当成价值？

## 路线要求

### Engine A：竞品验证

- 每个候选至少三个真实直接竞品；
- 核对官方产品能力、支持平台、监控对象、AI 分析与交付方式；
- 只选择跨竞品仍未稳定解决、且能用一到三个改变验证的任务；
- 两个候选必须服务不同的核心任务，不得只换名称。

### Engine B：市场缺口与第一性原理

- 至少三个真实替代方案或 workaround；
- 从“关注名单 → 获取新内容 → 判断相关性 → 形成证据 → 团队行动”重新设计最短闭环；
- 必须说明小团队为何不直接购买完整达人营销套件；
- 设计可在不建设违规爬虫的情况下完成的前置验证。

### Engine C：新需求

- 本轮目标数量为零；不生成候选、不借热点补位。

## 事实与合规

- 必须联网现查，不把模型记忆当作当前事实；
- 优先官方产品页、帮助中心、官方文档与可追溯用户讨论；
- 不伪造下载、收入、活跃、留存或全平台覆盖；
- 首版只使用官方 API、授权导出、RSS、公开网页和用户主动提交链接；
- AI 结论必须保留原文、作者、时间、来源和不确定性；
- 产品不得自动执行营销、投资、舆情处置或封禁决策。

## 最终产物

- A 路线独立入选 2 个，B 路线独立入选 1 个，C 路线 0 个；
- 每个项目只保留一到三个核心改进；
- 每个项目提供英文名与中文名、产品形态、参考对象类型和可点击链接；
- 为三个入选项目生成完整 `READY_FOR_BENCH` 资料包、ZIP 和 SHA-256；
- 生成正式报告、选择总表、证据、开发排期和网站数据；
- 通过 Schema、链接、数量、路线隔离、资料包完整性和公开内容安全检查；
- 成功后发布到既有统一网站，不推送飞书。
